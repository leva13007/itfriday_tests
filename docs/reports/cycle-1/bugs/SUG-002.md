# [SUGGESTION] Site-wide: enforce HTTPS

## Summary

The site is served over plain HTTP without redirecting to HTTPS.

## Current behaviour

- `curl -sI http://itfriday.community/` → `HTTP/1.1 200 OK`, full page, no `Location` header
- Same for inner pages, e.g. `http://itfriday.community/streams/022`
- `https://` responses have no `Strict-Transport-Security` header

Checked on 2026-10-07 (deploy `03ab24e`).

## Suggested behaviour

`http://` requests get a 301 redirect to `https://`. On GitHub Pages this is the "Enforce HTTPS" checkbox in the repository's Pages settings.

## Why it matters

Visitors who type the address without `https://`, or follow an old `http://` link, get an unencrypted page that can be modified in transit. Search engines may also index both versions.
