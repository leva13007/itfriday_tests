# [BUG] Header: logo link has no accessible name

## Summary

The logo link in the header (link to the home page) has no accessible name: its two `<img>` elements have an empty `alt` (`alt=""`, which marks an image as decorative), and the link has no other text or ARIA label. Screen readers announce it as an unlabelled link on every page.

## Environment

| | |
|---|---|
| URL | Every page, e.g. https://itfriday.community/ |
| Browser + version | Chrome 154, axe-core 4.10.2 |
| OS / device | macOS |
| Viewport | 1512×806 |
| Language | UA and EN |
| Deploy | Tue, 06 Oct 2026 16:47:41 GMT (site commit `03ab24e`) |

## Steps to reproduce

1. Open https://itfriday.community/.
2. Run an axe scan (axe DevTools → "Scan all of my page").
3. Or inspect the header logo: `a.title > img.VPImage`.

## Expected result

The logo link has an accessible name, e.g. the images have a non-empty `alt="IT Friday"`, so it is announced as "IT Friday, link" (REQ-014; WCAG 1.1.1, 2.4.4).

## Actual result

- axe: `link-name` (serious) on all 8 scanned pages, in both themes, target `a[href="/"]`.
- HTML: `<img class="VPImage dark logo" src="/logo-light.png" alt>` and the same for `/logo-dark.png`. A bare `alt` equals `alt=""`.

## Severity / Priority

| Severity | Priority |
|---|---|
| Major | Medium |

Major: the main "home" control on every page is unusable by name for screen reader users. A workaround exists (the nav menu).

## Evidence

axe results per page are in the [cycle 1 execution summary](../2026-10-07-execution-C1.md#accessibility-scan).

## Correction

2026-10-07, later the same day: the first version of this report said the images had **no** `alt` attribute. They have an **empty** one; the first check parsed the HTML for `alt="…"` and missed the bare `alt`. The defect and its impact are unchanged: the link has no name. Found while automating TC-A11Y-004.

## Related

- Requirement: REQ-014
- Test cases: TC-A11Y-001, TC-A11Y-004
- Reproducibility: Always
- Hint for the fix: the site hides the text title (`siteTitle: false`), so the logo needs `alt` (VitePress `logo: { light, dark, alt }`).
