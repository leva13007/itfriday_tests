## 1. Summary

The first full test cycle of itfriday.community covered all 17 requirements on the primary configuration (Chrome desktop, plus emulated mobile), with every page of the site included in the HTTP-level checks. **The core of the site works:** all 82 pages respond, navigation, language switching, content lists, internal and external links and the mobile layout pass. Cycle 1 found **7 bugs (0 Critical, 1 Major, 5 Minor, 1 Trivial)** and **5 improvement suggestions**. The main risks left are accessibility (the logo link has no name on every page), incomplete Ukrainian interface texts, and content consistency (schedule page, a speaker profile). Checks that need real devices or assistive technology (Safari, iPhone, keyboard, VoiceOver, visual baseline) were not run and remain open.

## 6. Recommendations and lessons learned

**For the site:**
1. **Before the 2026-10-09 stream:** update the schedule page (BUG-007).
2. Quick configuration wins that fix every page: logo `alt` (BUG-003), Ukrainian interface labels in the UA locale config (BUG-002), per-page descriptions (BUG-001).
3. Then: the #012 entry on the speaker profile (BUG-006), the `chrome://` link (BUG-005), and consider SUG-002 (one checkbox in GitHub Pages) and SUG-003 (images; the largest performance gain).

**For testing:**
- **Automate the consistency checks first** in phase 4: the streams × speakers × languages cross-check and the language-switcher sweep found real defects and take seconds to run.
- **Run sweeps over every page, not samples**, whenever the check is cheap. The sample-based plan would have missed BUG-005 and BUG-006.
- **Keep external link checks browser-verified.** 7 of 83 links answer scripts with 4xx/999 but work for people. Without a browser check they would be false bugs.
- **Exploratory testing needs the consistency oracle.** Two bugs had no written requirement and were still clearly defects. The strategy was updated to say so.
- **Know the automation limits:** keyboard input, full-page screenshots, real devices and screen readers weren't reliable or available here. Those checks need a person, or proper tooling in phase 3–4 (Playwright can do keyboard and full-page screenshots).
- One test case defect (TC-PST-001, too strict) was found and fixed. Expected results should allow legitimate variations.
