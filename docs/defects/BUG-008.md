# [BUG] Site root: repo files README.md and CLAUDE.md are published as pages

## Summary

The site repo's own `README.md` and `CLAUDE.md` (developer notes and AI-assistant instructions, not site content) are published on the live site as `/README` and `/CLAUDE`, because VitePress turns every `.md` file under its source folder into a page and the config excludes none.

## Environment

| | |
|---|---|
| URL | https://itfriday.community/README, https://itfriday.community/CLAUDE (also `/README.html`, `/CLAUDE.html`) |
| Browser + version | Chrome 154; curl |
| OS / device | macOS |
| Viewport | 1512×806 |
| Language | UA (the pages have no EN counterpart: `/en/README` and `/en/CLAUDE` return 404) |
| Deploy | Tue, 06 Oct 2026 16:47:40 GMT (site commit `03ab24e`) |

## Steps to reproduce

1. Run `curl -I https://itfriday.community/CLAUDE` and `curl -I https://itfriday.community/README`.
2. Open https://itfriday.community/CLAUDE in the browser.

## Expected result

Both URLs return 404. Only site content is published; files that describe the repo (README, contributor and assistant guidance) stay in the repo.

## Actual result

Both return HTTP 200 and render inside the normal site layout:

- `/CLAUDE`: title "site/CLAUDE.md | ІТ П'ятниця", text starts "Guidance for working inside the site/ folder (public community website)…" and describes internal conventions.
- `/README`: title "itfriday.community | ІТ П'ятниця", developer setup (`pnpm dev`, deployment notes).

The pages aren't linked from the navigation, but anyone can open them, and search engines can index them: they carry the site's normal meta tags and no `noindex`.

## Severity / Priority

| Severity | Priority |
|---|---|
| Minor | Medium |

Severity Minor: no secrets are exposed (checked: both files contain only public information) and no user flow is affected. It's still internal material on a public site, with an English-only page in the UA section and a confusing title in search results. Priority Medium: the fix is one config line.

## Evidence

- `curl -s -o /dev/null -w '%{http_code}'`: `/CLAUDE` 200, `/README` 200, `/CLAUDE.html` 200, `/README.html` 200, `/en/CLAUDE` 404, `/en/README` 404.
- Cause in the [site repo](https://github.com/leva13007/itfriday.community): `README.md` and `CLAUDE.md` sit in the repo root, which is also the VitePress source folder, and `.vitepress/config.ts` has no `srcExclude`. Possible fix: `srcExclude: ['README.md', 'CLAUDE.md']` (or `'**/CLAUDE.md'` if more of them appear in subfolders).
