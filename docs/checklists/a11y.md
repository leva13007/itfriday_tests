# Accessibility Checklist

Checks that the site can be used with a keyboard, a screen reader, and in less-than-ideal viewing conditions. The target is WCAG 2.2 level AA: the commonly expected baseline. This checklist covers its most important parts for a content site. It isn't a full WCAG audit.

| | |
|---|---|
| When | Once per cycle |
| Configuration | C1 (Chrome desktop) with the axe DevTools extension; C2 (Safari) for the VoiceOver checks |
| Duration | ~60 min |
| Version | 1.0 (2026-10-07) |
| Pass criterion (REQ-014) | No *critical* or *serious* axe violations; all manual checks below pass |

**How to run:** copy to `runs/YYYY-MM-DD-a11y.md`. Use ✅ / ❌ (bug link) / ⏭ (why skipped).

## B. Keyboard

Put the mouse away. Use only Tab, Shift+Tab, Enter, Space and Escape.

| # | Check | Expected | WCAG | Result | Bug / note |
|---|---|---|---|---|---|
| A11Y-B01 | Press Tab once on page load | A "Skip to content" link appears and works | 2.4.1 | | |
| A11Y-B02 | Tab through the header | Reaches logo, every nav item, language switcher, theme toggle, social icons in a logical order | 2.4.3 | | |
| A11Y-B03 | Focus visibility | Every focused element has a clearly visible focus indicator, in both themes | 2.4.7 | | |
| A11Y-B04 | Language switcher by keyboard | Opens with Enter/Space, options are reachable, Escape closes it | 2.1.1 | | |
| A11Y-B05 | Mobile menu by keyboard (narrow window) | Hamburger opens with Enter; items reachable; Escape or the close button closes it | 2.1.1 | | |
| A11Y-B06 | No keyboard trap | Focus never gets stuck. You can always Tab past any component | 2.1.2 | | |
| A11Y-B07 | Content links and buttons | All reachable and activated with Enter | 2.1.1 | | |
